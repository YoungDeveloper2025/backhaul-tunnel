# مدیریت تانل Backhaul روی اوبونتو

اسکریپت `backhaul-manager.sh` برای نصب و مدیریت [Backhaul](https://github.com/Musixal/Backhaul) نسخهٔ `v0.7.2` روی Ubuntu با معماری `amd64` یا `arm64` و `systemd` است. سرور ایران نقش **server** و سرور خارج نقش **client** دارد.

## گذاشتن در گیت‌هاب و اجرا

فایل `backhaul-manager.sh` را در شاخهٔ `main` مخزن خودتان قرار دهید. در دستور زیر `YOUR_USER` و `YOUR_REPO` را جایگزین کنید:

```bash
curl -fSL https://raw.githubusercontent.com/YoungDeveloper2025/backhaul-tunnel/main/backhaul-manager.sh -o backhaul-manager.sh
sudo bash backhaul-manager.sh
```

اگر `curl` نصب نیست، ابتدا آن را نصب کنید:

```bash
sudo apt-get update
sudo apt-get install -y curl
```

اسکریپت در شروع `apt-get update` را اجرا می‌کند، وابستگی‌ها را نصب می‌کند و فایل اجرایی Backhaul را در صورت نیاز دریافت می‌کند؛ سپس منو نمایش داده می‌شود. `apt-get upgrade` اجرا نمی‌شود. برای اجرای دوباره، دستور `sudo bash backhaul-manager.sh` کافی است.

## منو و ساخت تانل

منو شامل ساخت تانل، مدیریت تانل‌های موجود و خروج است. بخش مدیریت ویرایش، حذف، وضعیت و لاگ، راه‌اندازی مجدد، تست اتصال و نمایش کد اتصال را دارد. فقط تانل‌هایی که با این اسکریپت ساخته شده‌اند مدیریت می‌شوند.

برای ساخت از سرور خارج:

1. «ساخت تانل» و سپس «خارج / کلاینت» را انتخاب کنید.
2. حالت «اتومات» را انتخاب کنید.
3. نام پیش‌فرض `mytunnel` و انتقال پیش‌فرض `tcpmux` است؛ `tcp` هم قابل انتخاب است.
4. پورت‌های سرویس پیش‌فرض `443,2083,2053,1115,1117` هستند. هر پورت روی ایران به همان شماره پورت روی خارج هدایت می‌شود.
5. آی‌پی سرور ایران را وارد کنید؛ این سؤال پیش‌فرض ندارد.
6. برای ساخت سمت ایران از همین‌جا، پاسخ پیش‌فرض `y` را بپذیرید.
7. آی‌پی ایران همان مقدار مرحلهٔ قبل و پورت SSH پیش‌فرض `22` است. رمز SSH را وارد کنید؛ رمز هنگام تایپ قابل مشاهده است.

پورت ارتباط خود Backhaul از پورت‌های سرویس جداست. مقدار خودکار از `3080` شروع می‌شود و با توجه به پورت‌های انتخابی و تانل‌های ثبت‌شده روی همین سرور انتخاب می‌شود. اگر پورت ارتباط یا یکی از پورت‌های سرویس روی ایران اشغال باشد، نصب انجام نمی‌شود. برنامهٔ مقصد، مثلاً Xray، باید روی پورت‌های انتخابی در سرور خارج در حال گوش‌دادن باشد.

در نصب خودکار سمت ایران، ورود SSH با کاربر `root` و رمز عبور باید فعال باشد. اسکریپت خودش را به ایران انتقال می‌دهد؛ برای آن مرحله لازم نیست فایل از مخزن گیت‌هاب شما دریافت شود.

اگر تانلی با همان نام وجود داشته باشد، اسکریپت پیش از جایگزینی تأیید می‌گیرد و پاسخ پیش‌فرض `y` است. این بررسی هم برای تانل محلی و هم برای سمت ایران در نصب SSH انجام می‌شود. هر تانل سرویس مستقل `systemd` دارد و پس از ریبوت هم اجرا می‌شود.

پس از نصب دو سمت با SSH، آزمون اتصال اجرا می‌شود. آزمون، سرویس همان تانل را یک بار راه‌اندازی مجدد می‌کند و سپس احراز هویت Backhaul و اتصال TCP فعال متعلق به همان سرویس را بررسی می‌کند. گزینهٔ «تست اتصال» در منوی مدیریت نیز همین رفتار را دارد. پاسخ‌گویی سرویس‌های مقصد در خارج هم جداگانه بررسی می‌شود؛ این بررسی آزمون کامل عبور ترافیک هر سرویس از ایران نیست.

## نصب دستی

حالت دستی خارج علاوه بر سؤال‌های اصلی، پورت ارتباط، توکن، `connection_pool` و برای `tcpmux` مقدار `mux_con` را می‌پرسد. Enter در سؤال توکن، توکن تصادفی تولید می‌کند.

برای نصب ایران بدون SSH، کد اتصال نمایش‌داده‌شده در خارج را کپی کنید. اسکریپت را روی ایران اجرا کنید، «ساخت تانل» و «ایران / سرور» را انتخاب کنید و کد را در سؤال «کد اتصال» بچسبانید. کد حاوی توکن است و باید خصوصی بماند.

اگر در سؤال کد اتصال Enter بزنید، تنظیمات ایران را دستی وارد می‌کنید. انتقال، پورت ارتباط و توکن باید با سمت خارج یکسان باشند؛ توکن جدید مستقلی برای ایران نسازید.

هنگام ویرایش تانل خارج، می‌توانید تنظیمات ایران را نیز از طریق SSH جایگزین کنید. حذف تانل فقط روی همان سرور انجام می‌شود؛ برای حذف سمت دیگر، اسکریپت را روی همان سمت اجرا کنید.

## شبکه و نگهداری

- پورت ارتباط Backhaul باید روی سرور ایران برای دسترسی کلاینت خارج باز باشد.
- پورت‌های سرویس باید روی سرور ایران برای کاربران باز باشند.
- قواعد فایروال سرور و پنل ارائه‌دهنده را بررسی کنید؛ اسکریپت قواعد فایروال را خودکار تغییر نمی‌دهد.
- موفق‌شدن آزمون تانل به‌تنهایی به معنی آماده‌بودن همهٔ سرویس‌های مقصد نیست؛ سرویس هر پورت را جداگانه بررسی کنید.
- فایل دانلودشده را نگه دارید تا برای مدیریت بعدی دوباره اجرا کنید.

پیش از جایگزینی، نسخهٔ قبلی در `/etc/backhaul-manager/backups` نگهداری می‌شود. اگر بازیابی تنظیمات قبلی ناموفق باشد، اسکریپت مسیر نسخهٔ نگهداری‌شده را اعلام می‌کند.

تنظیمات تانل `mytunnel` در مسیر زیر نگهداری می‌شوند:

```text
/etc/backhaul-manager/tunnels/mytunnel/metadata.json
/etc/backhaul-manager/tunnels/mytunnel/config.toml
```

برای دیدن لاگ این تانل از منوی مدیریت یا دستور زیر استفاده کنید:

```bash
sudo journalctl -u backhaul-manager-mytunnel.service -n 50 --no-pager
```
